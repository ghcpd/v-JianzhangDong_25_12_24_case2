Assignment: Add missing documentation and automated tests

Objective
- Find and add any missing module, class, and function/method docstrings across the repository without changing program logic.
- Add an automated test runner to verify the presence of docstrings and an auto-test wrapper that detects the environment, executes the correct test script, and writes a timestamped log with a final status line.

Requirements
1. Virtual Environment
   - Create a clean virtual environment under `.venv/`.
   - Do not reuse any existing environment: if `.venv/` exists, delete and recreate it.
   - Install all dependencies from `requirements.txt` into `.venv/`.
   - Update `.gitignore` to ensure `.venv/` (and `logs/`, `__pycache__/`) are ignored.

2. Documentation Reference
   - Create `reference_link.txt` documenting each missing docstring using this exact format:
     (1) path/to/module.py: Missing module docstring (line 1)
     (2) path/to/module.py: Missing function docstring for func_name() (line N)
     (3) path/to/module.py: Missing class docstring for ClassName (line N)
   - Keep the numbering sequential and list every missing module/class/function found before changes.

3. Add Missing Docstrings
   - Add missing module/class/function docstrings only. Do not change existing code or logic.
   - Docstrings should be concise and clear (1-3 sentences) describing purpose and behavior.

4. Automated Tests and Runner
   - Implement `run_tests.py` that verifies module, class, and function/method docstrings (use AST introspection).
   - Provide platform scripts: `run_test.sh` (Linux/macOS) and `run_test.bat` (Windows) to execute `run_tests.py`.
   - Implement `auto_test.py`:
     - Detect environment (Windows/Linux/Docker) and execute the appropriate platform script.
     - Save all output to `logs/test_run.log`.
     - Log must include a timestamp at the start and a final status line exactly: `TEST PASSED` or `TEST FAILED`.

Acceptance Criteria
- `reference_link.txt` exists and documents the originally missing docstrings in the specified format.
- All previously missing module/class/function docstrings are added (no logic changes).
- `run_tests.py`, `run_test.sh`, `run_test.bat`, and `auto_test.py` are present and runnable.
- Running `python auto_test.py` appends human-readable logs to `logs/test_run.log` that contain a timestamp and final status line (`TEST PASSED` or `TEST FAILED`).
- `.gitignore` includes `.venv/` and `logs/`.

Notes & Troubleshooting
- Dependency compile issues: Some packages (e.g., `pydantic-core`) may require Rust/Cargo to build from source on certain Python/OS combos. If `pip install -r requirements.txt` fails with Rust-related errors, choose one of:
  - Install the Rust toolchain (via `rustup`) in the environment and retry; or
  - Use a Python version with prebuilt wheels for the package (e.g., switch to a supported Python minor version where wheels are available).
- The docstring tests should not rely on fully installing optional/compiling-only packages. The test suite may operate independently of compiled-only packages.

How to Run (developer instructions)
1. Remove and recreate the venv:
   - Windows (PowerShell):
     Remove-Item -Recurse -Force .venv -ErrorAction SilentlyContinue; python -m venv .venv; .\.venv\Scripts\python -m pip install --upgrade pip; .\.venv\Scripts\python -m pip install -r requirements.txt
2. Run auto-tests:
   - python auto_test.py
3. Check results:
   - Open `logs/test_run.log` and confirm the timestamp and a final line `TEST PASSED`.

Expected Files to be added/modified as part of this task
- Modified: modules with added docstrings (e.g., `api.py`, `tasks.py`, `utils.py`, `app.py`, `config.py`)
- Added: `reference_link.txt`, `run_tests.py`, `run_test.sh`, `run_test.bat`, `auto_test.py`, `.gitignore` (if missing/updated to ignore `.venv/`, `logs/`)

Success = All acceptance criteria satisfied and `python auto_test.py` produces a log with `TEST PASSED`.
